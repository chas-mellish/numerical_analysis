# Chapter 4, Program 1: Derivatives by central differences

*Book page 90, chapter 4 "Numerical Differentiation", Program 1. Catalog entry:
`catalog/ch04_p01_central_difference.toml`. The listing exists only as a scan
(`legacy_code/fortran/chapter_4/derivatives.pdf`); there is no OCR text of it.*

## The method

Expand F in Taylor series on both sides of X:

    F(X ± H) = F(X) ± H F'(X) + H²/2 F''(X) ± H³/6 F'''(X) + H⁴/24 F''''(X) ± …

Subtracting the two series cancels the even terms, adding them cancels the odd ones:

    DX  = (F(X+H) − F(X−H)) / (2H)          = F'(X)  + H²/6  F'''(X)  + O(H⁴)
    DDX = (F(X+H) − 2F(X) + F(X−H)) / H²    = F''(X) + H²/12 F''''(X) + O(H⁴)

Both **central-difference formulas** are second order: dividing H by ten divides the truncation
error by about 100. One-sided differences, (F(X+H) − F(X))/H, are only first order.

Making H small has a price. The numerators are differences of nearly equal numbers: if F is known
to a relative precision ε (the machine's), the round-off error of DX is about ε|F|/H and that of
DDX about 4ε|F|/H². The total error therefore falls like H² until round-off takes over, and then
grows again. The best H balances the two terms (about ε^(1/3) for DX and ε^(1/4) for DDX).

Gerald's program shows exactly this. It reads X and a starting H, evaluates `FO = F(X)` once (the
letter O: F at the centre, next to `FR` on the right and `FL` on the left), and prints DX and DDX
for ten values of H, dividing H by ten after every row with `10 H = 0.1*H`. Two details of the
listing are worth noticing:

* **H is accumulated.** `H = 0.1*H` multiplies the previous H, so on a binary machine the rows do
  not use exact powers of ten (real64 row 10 has H = 1.0000000000000006·10⁻¹⁰). Both modern engines
  accumulate H the same way and agree bit for bit.
* **There is no stopping test.** The program always prints ten rows; the learner judges where the
  values are best. The modern `value` is the DX of the last row, the program's final estimate.

The same order-of-error reasoning reappears in chapter 5: the formula summary on book p. 106
(`legacy_code/fortran/chapter_5/integration_methods.pdf`, a page of formulas without a program)
lists the local errors −h³/12 f'' of the trapezoidal rule and −h⁵/90 f⁗ of Simpson's rule, the
integration counterparts of the H²/6 and H²/12 terms above.

## The book's data card

The function is the statement-function card `F(X) = X**2*EXPF(X)`. Its derivatives at X = 0 are
F'(0) = 0 and F''(0) = 2. The data card, read with `FORMAT (2F10.0)`, holds X and H:

```
0.0       0.1
```

The book's output (formats 200 and 201):

```
DERIVATIVES COMPUTED BY CENTRAL DIFFERENCE FORMULAS
AT X =  0.00

   H             DX                 DDX

 1.0E-01      1.0016675E-02      2.0100083E+00
 1.0E-02      1.0000150E-04      2.0000999E+00
 1.0E-03      9.9995000E-07      2.0000009E+00
 1.0E-04      1.0000000E-08      2.0000000E+00
 1.0E-05      9.9500000E-11      1.9999999E+00
 1.0E-06      9.5000000E-13      1.9999999E+00
 1.0E-07      5.0000000E-15      1.9999999E+00
 1.0E-08      0.0000000E-99      2.0000000E+00
 1.0E-09      0.0000000E-99      2.0000000E+00
 1.0E-10      0.0000000E-99      2.0000000E+00
```

The text above the listing explains it: "The values of the second derivative, whose analytical value
is 2, show an oscillatory behavior due to round-off. The first derivative values converge
monotonically to zero." At X = 0 the formulas give exactly DX = H·sinh(H) ≈ H² and
DDX = 2·cosh(H) ≈ 2 + H², so DX *is* the truncation error of the first derivative.

The chart plots DX and DDX against H on logarithmic axes, and the change from one row to the next,
which estimates the error of each row: it falls by a factor of about 100 per row as long as the
truncation error dominates.

The book's next page (p. 91, `legacy_code/fortran/chapter_4/derivatives_log_example.pdf`, linked in
the Legacy tab; it holds problems 2–7 and no program) asks in problem 2 for d(1 + log x)/dx at
x = 0.15, 0.19, 0.23 from a four-decimal table with spacing 0.02. Preset 3 is that function,
1 + log₁₀ x, whose derivative is 1/(x ln 10); two practice questions below use it.

## Precision

The book's digits for small H are round-off of its machine, which kept about 8 decimal digits:

* **DX**, a cancellation (F(X+H) − F(X−H) is only about 2H of F(X+H)), loses its digits as H
  shrinks: the book prints **1.0000150E-04** at H = 10⁻² (true 1.0000167·10⁻⁴), **9.9995000E-07** at
  10⁻³, **5.0000000E-15** at 10⁻⁷ and **0.0000000E-99** from 10⁻⁸ on, where its F(X+H) and F(X−H)
  became equal.
* **DDX** has no cancellation at X = 0, because F(0) = 0: it stays within a unit of the eighth
  digit of 2 (2.0000999, 2.0000009, 1.9999999 — the "oscillatory behavior" of the text).

A modern **real64** run keeps 16 digits, so every row stays close to H·sinh(H): row 2 prints
**1.0000166E-04** (0.00010000166667499881), the last row **1.0000000E-20** (the value
1.0000000031710762·10⁻²⁰), and DDX is 2.0001000 at H = 10⁻² and exactly 2.0 from H = 10⁻⁸ on.
The first row agrees with the book: DX = 0.010016675001984412 (book 1.0016675E-02) and
DDX = 2.010008336111607 (book 2.0100083E+00). A **real32** build (`make build-fortran-single`)
behaves like the book: EXP(H) rounds to 1 below H ≈ 6·10⁻⁸, so its DX is exactly zero in the last
three rows.

The golden tests compare H within 10⁻¹², DX within 2·10⁻⁹ and DDX within 2·10⁻⁷ of the book (real32:
10⁻⁸, 10⁻⁸ and 10⁻⁶); the book's largest DX deviation, 1.7·10⁻⁹ at H = 10⁻², is a cancellation
error of its machine. The well-conditioned first row is checked on its own within one unit of the
last printed digit, and real64 runs are pinned to their exact values. An absolute tolerance on the
tiny DX of the later rows does not test their digits: those digits are round-off on every machine,
which is the lesson of the program.

The printout itself differs from modern Fortran in three ways, all reproduced in the book text
(erratum `book-number-format`): the book's `E14.7` printed one digit before the point
(`1.0016675E-02`, modern `ES14.7`; standard `E14.7` would print `0.1001667E-01`), an exact zero
printed as `0.0000000E-99`, and `F5.2` kept its leading zero (`0.00`). DX and DDX are chopped like
the other book printouts; X and H are rounded to nearest, since chopping their binary values would
print X = .29 as 0.28. The book's computer is not identified (see `docs/architecture.md`, "The
book's computer"): the `ZZJOB` cards and the −99 exponent of zero resemble the IBM 1620, but the
question stays open. Replaying the listing in chopped arithmetic
(`gerald_na.tools.book_machine.central_difference_rows`, 8- and 9-digit decimal and 27-bit binary
models with a correctly rounded EXP) does not reproduce the book's small-H DX digits either: the
8-digit decimal model gives 1.0000135E-04 for row 2 where the book has 1.0000150E-04. Those digits
depend on the machine's own `EXPF` routine, which is unknown.

## Practice questions

The answers are checked by running an engine with the stated inputs (catalog `practice` ids in
brackets).

1. **[book-first-dx]** Run the book's data card (0.0 0.1). What DX does the first row give? Why is
   it not 0, the true F'(0)?
2. **[rows]** How many rows does the program print, and what is the last H?
3. **[book-last-ddx]** What DDX does a real64 run print for the last row? Why does the book print
   1.9999999 for some rows?
4. **[sin-second-derivative]** Select preset 2, sin(x), with X = 1.0 and H = 0.1. What DDX does the
   first row give? Compare its error with H²/12 · F⁗(1).
5. **[log-table-derivative]** Book p. 91, problem 2: select preset 3, 1 + log₁₀ x, with X = 0.19
   and H = 0.02. What DX does the first row give, and how far is it from 1/(0.19 ln 10)?
6. **[log-smallest-h]** Same run: what DX does the last row (H = 2·10⁻¹¹) give? Which row comes
   closest to the analytical value, and why do the last rows get worse?
