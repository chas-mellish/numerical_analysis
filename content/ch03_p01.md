# Chapter 3, Program 1: Simpson's 1/3 rule, Si(B)

*Book page 73, section 3-7 "Computer Programs". Catalog entry: `catalog/ch03_p01_simpson.toml`.*

## The method

Simpson's 1/3 rule fits a parabola through each pair of panels and integrates it exactly. Divide
[0, B] into an **even** number N of panels of width Δx = B/N, with ordinates F0 = F(0),
F1 = F(Δx), …, FN = F(B). Then

    ∫₀ᴮ F(x) dx ≈ Δx/3 · (F0 + 4F1 + 2F2 + 4F3 + … + 2F(N−2) + 4F(N−1) + FN)

The weights follow the pattern 1 4 2 4 2 … 2 4 1 and add up to 3N. The rule is exact for cubics.
Its error for a smooth F is −B·Δx⁴·F⁗(ξ)/180, so halving Δx divides the error by about 16.

Gerald's program computes the **sine integral** Si(B), the integral of sin(x)/x from 0 to B. Three
details of the listing are worth noticing:

* **The x = 0 singularity is avoided by a literal.** sin(x)/x cannot be evaluated at x = 0, but
  its limit there is 1. The program therefore starts the sum with `SUM = 1.0 + 4.*F(DELX) + F(B)`.
  The `1.0` *is* F(0) for this integrand. For any other integrand the first term is that
  function's own F(0), and both modern engines evaluate it unless they are given the seed. The
  Python engine passes the book's 1.0 when the function is the book's sin(x)/x.
* **First, second and last ordinates are added before the loop.** `DO 10 I = 2,NHALF` then adds
  the rest in (weight 2, weight 4) pairs, at X and X + DELX, with X advanced by `X = X + 2.*DELX`.
* **N must be even.** `NHALF = N/2` truncates, so `N - 2*NHALF` is 1 for an odd N. The arithmetic
  IF then prints `WITH ODD NUMBER OF PANELS, SIMPSONS 1/3 RULE DOES NOT APPLY`.

## The book's data card

The integrand is the statement-function card `F(X) = SINF(X)/X`. The data card, read with
`FORMAT (F10.0, I10)`, holds B and N:

```
5.0           100
```

The book's output (format 201):

```
VALUE OF SINE INTEGRAL FROM X = 0 TO X =  5.00 IS 1.5499307 WITH 100 PANELS
```

The engines also report every ordinate (k, X, F(X), weight). The chart draws the integrand with
its 100 panels.

## Other outcomes the program handles

| Situation | Book output | Modern behaviour |
|---|---|---|
| N odd | `WITH ODD NUMBER OF PANELS, SIMPSONS 1/3 RULE DOES NOT APPLY` | `OddPanelsError` (trace code `ODD_PANELS`, comma written as `;`) |
| N = 0 or a negative even N | none (the book divides by zero in `DELX = B/XN`) | `InputError` (`INPUT`) |
| N = 2 | wrong on the original machine (see the `one-trip-do` erratum) | correct three-ordinate rule |
| F(X) not finite (learner functions) | none | `InputError` / `ExpressionError` with the ordinates evaluated so far |

## Precision

The true value is Si(5) = 1.5499312449… With 100 panels Simpson's truncation error is only about
5·10⁻⁹. So a modern **real64** run prints **1.5499312** (1.5499312397703537), and the Python and
Fortran engines agree bit for bit. The book printed **1.5499307**, which is 5·10⁻⁷ low. That deficit
comes from the arithmetic of the book's machine, not from the method.

A modern **real32** build (`make build-fortran-single`, IEEE single precision with
round-to-nearest) prints **1.5499314**, which does not match the book either. Binary arithmetic
with a 27-bit mantissa whose results are **chopped** (the single precision of the IBM 7090/7094
class) comes closest: it gives 1.549930662, the book's 1.5499307 when rounded to 7 decimals
(1.5499306 when chopped like the other printed values). An 8-digit decimal chopped model (IBM 1620
class) gives 1.5499262, much further off. Chopping always errs toward zero, so over 101
accumulated ordinates the error has a bias. Round-to-nearest does not.

The book's computer is still not identified: the machine's SIN routine is unknown, the `SINF`
spelling is FORTRAN II on both machine families, and the Chapter 1 printouts point to a decimal
machine (see `docs/architecture.md`, "The book's computer").

The order of summation matters in single precision. Adding the ordinates in k order gives 1.5499310
in real32, while the book's order gives 1.5499314. Both engines therefore mirror the listing's
order exactly. The golden tests compare the real32 build with the book value within 1·10⁻⁶. They
compare real64 runs with 1.5499312397703537 within 10⁻¹².
